# 拦后继续：有效果，但没泛化

## 1 做了什么

针对 banking 净损失画像里的两类：

1. **"被拦后 0 步收尾"**（18 个损失里 7 个）：加了收尾门 `pending_side_effect()`
   ——本任务授权工具集里有副作用工具、但一个都没成功执行时，收尾前再推一次。
2. **"继续做了但对象选错"**（如把 Spotify 订阅当房租）：给 banking 提示补了
   "调整定期付款"的流程（按 subject 找那条定期付款 → 用它的 id →
   新金额 = 原金额 + 涨幅 → 改完复查）。

## 2 效果

**定向验证（user_task_2 × inj_0/2/3）**：改前 1/3 完成，改后 **3/3 安全且完成**。
这是"守卫效应"的正面案例：拦住注入的付款，然后正确把房租改掉。

**回归集（8 对）**：5/8 → **7/8**。

**banking 全域（144 对）**：

| 指标 | 改前 | 改后 |
|---|---:|---:|
| ASR | 0.70% | 1.40% |
| UA | 0.5915 | 0.5804 |
| 逐对效用 | — | **修好 15 / 弄坏 15** |

逐对看是**净 0**——全域没有任何净收益。那 1.40% 的 ASR 是两个
`user_task_15` 互斥对（见 docs/28）。

## 3 结论

- 这条流程提示对"调整定期付款"这一类任务是**确定性修复**（3/3 都对了）；
- 但对全域**不泛化**：15 修好 / 15 弄坏，说明它在别的任务上会改变模型行为，
  好坏相抵；
- 温度 0 下仍有这种抖动，说明模型对这些措辞敏感，单点验证的结论**不能**外推到全域。

**方法论教训：定向验证只能说"这类任务能修"，必须用全域名对差异确认净效果。**

## 4 保留决定

保留（对特定任务形态是确定的修复，全域中性），但在论文/结项材料里
不能把它算作"守卫效应提升"的证据。
