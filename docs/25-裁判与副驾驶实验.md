# 两项尝试的结果（审核表裁判 / 守卫副驾驶）

## 1 审核表裁判：净负，已回退

**做法**：把裁判从"自由文本给结论"改成"四行审核表 + 代码机械导出结论"
（工具在 T / 对象在 O / 参数可溯源 / 未借外部内容扩权，任一行为 not_ok 即拒绝）。

| 切片（25 对） | 自由裁判 | 审核表裁判 |
|---|---:|---:|
| slack | **4.00% / 0.68** | 12.00% / 0.72 |
| workspace | 0.00% / **0.76** | 0.00% / 0.72 |

slack 的 ASR 从 4% 涨到 12%，workspace 的 UA 掉 0.04。**表格让裁判更容易"四行都写 ok"**，
反而放松了判定。已回退。

结论：**裁判的问题不在输出格式，而在判据本身**（对"委托的必要性"不信任）。

## 2 守卫副驾驶：ASR 改善，效用持平

**做法**：拒绝时从授权范围里给出**具体可用的信息**——授权对象清单、
允许的办理类工具、以及"本次是否只允许查询"。依据是 travel 的守卫几乎不提升效用
（+0.034 vs 报告 +0.379），而两边无防御基线相同。

| travel 140 对 | ASR | UA |
|---|---:|---:|
| 原版 | 4.29% | 0.2929 |
| **副驾驶** | **2.86%** | 0.2786 |

25 对切片上看着像 +0.10（0.42→0.52），**全域复测是噪声**。
净效果：ASR 改善 1.4pp，UA 持平（差 0.014，远小于 140 对的噪声 0.04）。

保留（安全更好，效用不损），但它不是缺失的那块。

## 3 这两次尝试说明了什么

报告里"守卫提升效用"的效应（travel +0.379、workspace +0.138）**不是靠
"拒绝时多说几句"能复现的**。我们试过并已量化：

| 拒绝文案的变体 | 效果 |
|---|---|
| 只说"越权，别重试" | 基线 |
| 状态报告（讲清已完成/不是失败） | +0.03（banking） |
| 可操作原因（给出正确取值） | 净负 |
| 定向续做（想收尾时再推一次） | 0（只有 7 对受影响） |
| 副驾驶（给出授权对象与可用工具） | ASR −1.4pp，UA 持平 |

## 4 结论

守卫的"拦截"我们已经做对了（banking ASR 0.00%，四域 ASR 2.9% vs 报告 0.64%）。
**"拦截之后如何让效用上升"这一层，在文档给定的信息下我们复现不出来。**

要么报告的实现里有一层没写出来的东西（例如守卫替模型做了部分规划），
要么当年的实验条件与描述有出入。
