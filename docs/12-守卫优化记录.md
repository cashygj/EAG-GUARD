# 守卫优化记录：从 0.36 往 0.67 走

## 1 起点

用 `qwen-plus-2025-04-28` 跑满 slack 105 对：

| | ASR | UA |
|---|---:|---:|
| 报告 | 1.90% | 0.6667 |
| 本实现（安全档） | **1.92%** | 0.3558 |
| 本实现（清单授权） | 9.52% | 0.4190 |

ASR 已经对齐；差的是效用 0.25，且集中在"按标准选对象"的 11 个任务上
（`user_task_5/7/8/9/10~14/18~20`）。

## 2 这轮做的四次尝试

| 尝试 | 结果 | 判断 |
|---|---|---|
| 裁判只看结构化记录（不看原文） | 切片持平，5–9 组 0.20→0.12 | 方向对（不受注入影响），但更依赖归因 |
| 清单类读取算"已授权" | 5–9 组 0.12→0.36，全域 0.36→0.42 | 有效，但 ASR 1.92%→9.52% |
| 候选集交给裁判 | 5–9 组 0.36→0.32 | 无效 |
| 参数书写修复（引号/大小写） | 修好一个真 bug（改副本没改原值） | 必要但不充分 |
| 唯一前缀补全（`External_`→`External_0`） | 7–9 仍全 0，ASR 13%→20% | 无效，已回退 |

## 3 为什么 7–9 修不动

直接查环境：

```
channels: ['general', 'random', 'private', 'External_0']
add_user_to_channel(channel='External_', user='Charlie')
  → ValueError: Channel External_ not found in the channels list
```

模型读了 `get_channels`（清单里有 `External_0`），却一直传 `External_`——
**抄漏了一个字符**。守卫能做的只有：
- 纯书写层的修复（引号、大小写、空白）——已做；
- 唯一前缀补全——试了，反而让 ASR 涨（攻击者也可能利用补全撞到目标）。

再往下就要猜"模型想选哪个"，那就是在替模型做决定，不安全。

## 4 结论

守卫侧能做的已经做完：

- 归因：清单类/内容类已区分
- 裁判：不看原文，只看结构化记录 + 候选集
- 参数：书写层修复 + 执行前指纹核对
- 安全：ASR 1.92%，与报告 1.90% 对齐

剩下的 0.25 效用差，**主要不在守卫**，而在：

1. 模型抄错参数值（`External_` vs `External_0`）——占 7–9 三题；
2. 模型选错对象后不再纠正；
3. 少数任务里裁判仍然过严。

## 5 下一步的可选项

| 方向 | 预期 | 代价 |
|---|---|---|
| 接受安全档（1.92% / 0.36） | — | 无 |
| 换更强的 agent scaffold（更多轮、工具调用重试） | 可能 +0.1~0.2 | 中 |
| 给守卫加"环境求值"（自己算出应选对象） | 可能 +0.15 | 大 |
| 换模型（qwen-max）再测 | 未知 | 小 |

建议先做"换模型再测"——最便宜，且能直接回答"是不是模型能力问题"。
