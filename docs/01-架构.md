# 架构：报告概念到代码的映射

## 1 三层结构（报告 §2.1）

```
用户请求 u
   │  parse（只读 u，绝不读工具返回）
   ▼
授权范围 A=(T,O,P) ──────────────┐
   │                              │
   │  planner 提议动作             │  证据（带来源标签）
   ▼                              │
动作 a ──► attributor 归因 s(v) ──┼──► EAG 图（节点+边）
   │                              │
   ▼                              │
① FPR 结构判定（工具/对象/来源）    │
② 独立语义裁判（看不到 intent）     │
③ 执行前二次核对（签名比对）        │
   │                              │
   ▼                              │
执行 ──► 结果切分为证据 ────────────┘
   │
   ▼
④ 输出审核 ──► 最终回答
```

## 2 概念对照

| 报告 | 代码 |
|---|---|
| `u` 用户请求 | `EAG.add_user_request` |
| `A=(T,O,P)` | `scope.AuthorizationScope`，解析器 `RuleScopeParser` / 待接的 LLM 版 |
| `s(v)` 三分类 | `types.Provenance`；判定在 `provenance.Attributor` |
| 证据—授权—动作图 | `eag.EAG`，节点 `NodeKind`、边 `EdgeRel` |
| 字段级溯源可达性 FPR | `EAG.fpr()`，沿 `supports/derives` 反向 BFS |
| 独立语义裁判 | `judge.LLMJudge`（`JudgeView` 刻意不含 `Action.intent`） |
| 执行前核对 | `Guard.run` 第 ③ 步 |
| 拒绝 → 可操作原因 → 重规划 | `Planner.reject(reasons)`；`GuardConfig.feedback` 控制强弱 |
| 输出审核 | `audit.OutputAudit`（逐字重合 ≥32 字符即裁剪） |

## 3 判定顺序与理由

1. **FPR 先行**：纯结构、零成本、可解释。工具不在 `T`、对象不在 `O`、参数只溯源到不可信证据，直接拒。
2. **裁判复核**：结构判定答不了"用户到底委托了什么"，交给独立语义裁判；它只看到用户请求、授权范围、候选动作、参数来源，看不到规划器的自述理由——否则被污染的前提会自证清白。
3. **执行前二次核对**：判定的是签名 `tool(args)`，执行的必须还是它。防的是审核与执行之间的时间差（TOCTOU）。
4. **输出审核**：文本出口同样可能泄露或传播注入内容，报告 §2.3 第 3 阶段。

## 4 委托的两种形态（关键设计）

报告只说"用户指定字段由某来源在运行时取值"，实现时必须再分一层，否则委托会变成扩权通道：

- **字段型**（`mode="field"`）：取值必须等于证据的**结构化字段**。
  例：金额只能取 `evidence.fields["amount"]`。注入正文里另写一个"9999"不会被当成委托值。
- **内容型**（`mode="content"`）：用户要求"转发/摘要这段内容"，取值本来就是一段不可信文本，允许按内容匹配。

> 这条区分是 mock 里 `banking-amount` 用例存在的原因：金额被委托、正文被注入改数，
> 只看"值出现在被委托来源里"就会放行，必须看字段。

## 5 图上的边

```
u ──grants──► authorization(tool/object)
u ──delegates──► delegation(payee←inbox)
delegation ──derives──► param(payee=vendor@…)
evidence(untrusted) ──supports──► param(payee=attacker@…)
action ──supports──► param
action ──produces──► evidence
```

FPR 从 `param` 出发反向找根：落到 `authorization / delegation / user_request` 即放行；只落到不可信 `evidence` 即拒绝。

## 6 有意保留的简化（重建时要补）

- 解析器是规则版（辞书 + 正则），真实实验换成一次 LLM 调用，并对其输出做模式校验。
- 规划器是脚本队列，真实实验是 ReAct 式循环，拒绝后如何重规划要按域调。
- 证据切分按工具硬编码；真实环境需要统一的"来源标签"协议。
- 裁判只有一种提示词；报告里的"严格度"消融（白名单/线索/无 scope）还没做成配置。
- 没有缓存、没有并发、没有成本核算——这些在接真实模型时必须先有。
