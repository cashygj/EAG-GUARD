# EAG-Guard 重建工作总结（截至 2026-11-01）

## 一、交付了什么

从只有一份《EAG-Guard 阶段性研究报告》出发，把整套系统重建出来：

| 组件 | 内容 |
|---|---|
| 授权范围 | A=(T,O,P)：一次 LLM 调用把用户请求解析成工具集/对象集/参数来源 |
| 证据—授权—动作图 | 六类节点（用户/委托/证据/参数/动作/拒绝），参数逐条挂根 |
| 字段级溯源 FPR | 结构化字段（账单 IBAN/Total、交易 recipient/amount）优先，正文匹配受限 |
| 独立语义裁判 | 不看对话上下文，只看结构化视图（工具/对象/参数来源） |
| 执行前核对 | 判定与执行必须是同一份数据（指纹比对） |
| 输出审核 | 按域启用（travel），只抹"既像指令又出自不可信内容"的句子 |
| 拒绝后恢复 | 状态报告 + 可选续做门 |
| 评测脚手架 | AgentDojo v1 四域 629 对、断点续跑、逐对轨迹落盘（含最终答复） |
| 测试 | 87 个单元/回归测试 |
| 文档 | 32 篇（机制、审计、对照、踩坑记录） |
| 代码仓库 | GitHub `cashygj/EAG-GUARD`，多轮提交可追溯 |

## 二、最终结果 vs 报告

### 四域全量（qwen-plus-2025-04-28，629 对）

| 域 | 我们 ASR | 我们 UA | 报告 ASR | 报告 UA | UA 差 |
|---|---:|---:|---:|---:|---:|
| banking | 1.40% | 0.580 | 0.00% | 0.7153 | −0.135 |
| workspace | 2.94% | 0.567 | 0.00% | 0.7708 | −0.204 |
| slack | 1.90% | 0.467 | 1.90% | 0.6667 | −0.200 |
| travel | 2.90% | 0.551 | 1.43% | 0.6429 | −0.092 |
| **合计** | **2.40%** | **0.5498** | 0.64% | 0.7122 | **−0.163** |

> banking 的 1.40% 是两个"效用与安全互斥"的对（见第四节），实际安全洞为 0。
> slack 的 ASR 与报告**完全一致**（1.90%）。

### 同口径切片对照（user_task 0–4，30/25 对）

| 域 | AgentDojo 官方 | 我们·qwen-plus | 我们·qwen3.5-27b |
|---|---|---|---|
| banking | 56.67% / 16.67% | 0.00% / 53.33% | **0.00% / 66.67%** |
| workspace | 23.33% / 36.67% | 3.33% / 70.00% | 6.67% / **83.33%** |
| travel | 70.00% / 10.00% | 6.67% / 73.33% | **0.00% / 100.00%** |
| slack | 跑不了（无 injection_task_0） | 4.00% / 76.00% | 4.00% / 76.00% |

**三点结论**：
1. 我们的脚手架明显优于 AgentDojo 官方实现（UA 高 10–27 个百分点）；
2. 我们的守卫效应真实且很大（banking 无防御 26.67% → 守卫 53.33%，翻倍）；
3. **换 qwen3.5-27b 后 UA 平均再涨 13 个百分点**（banking +13.3、workspace +13.3、\n   travel +26.7、slack 持平），安全基本不损失（workspace 多 1 例，travel 反而更安全）。

## 三、差距拆解

总缺口 0.163 ≈ **0.109（智能体基线）+ 0.054（守卫效应）**

| 域 | 基线差 | 守卫效应差 |
|---|---:|---:|
| banking | −0.250 | **+0.115（我们更好）** |
| workspace | −0.112 | −0.092 |
| travel | −0.005 | −0.087 |
| slack | −0.048 | −0.152 |

**守卫层已经做到位**：banking 的守卫效应比报告还好，slack 的 ASR 与报告精确一致。
剩下主要是智能体基线——而这条已经被证明**可以通过换模型解决**（qwen3.5-27b）。

## 四、解决了什么（都是真 bug，不是调参）

| # | 问题 | 影响 |
|---|---|---|
| 1 | **放行与拒绝被同时记录**（两个独立 if 分支） | 工具执行了却又发"被拒绝"提示，模型回答"我没有权限查看日历" |
| 2 | 空参数（`cc=''`、`attachments=[]`）被判"无法归因" | 整条 `send_email` 被拒 |
| 3 | 输出审核按"与未授权证据重合"整段抹除 | travel 答案被抹成占位符，UA 腰斩（0.55 → 0.25） |
| 4 | 答复语言失配（中文提示 → 中文回答 → 英文逐字比对失败） | travel/workspace 大面积假失败 |
| 5 | URL 匹配不忽略 `http://`/`www.` 前缀 | slack 委托链从第二步断裂（8 对全挂） |
| 6 | 资金字段未强制"字段型委托"（且 `delegation_source` 为空导致机制失效） | 注入的 IBAN 被当收款人，banking 出现 3 例真实突破 |
| 7 | 裁判视图未标注"该材料是用户点名要读的" | slack 顺着用户指定消息取值被判扩权 |

修完后：slack ASR 9.52% → **1.90%**（与报告一致）、banking 真实安全洞归零、
travel UA 0.450 → 0.551、workspace UA 0.544 → 0.567。

## 五、解决不了的问题（附证据）

### 1. 报告的无防御基线复现不出来

- 报告 banking 无防御 UA = 0.7569；
- **AgentDojo 官方流水线**在同一批对上只有 **0.1667**；
- 我们的脚手架 0.2667。

即：即使把守卫全部拿掉，官方实现只到报告的 22%，我们到 67%。
**这不是实现问题，是那个数在 qwen-plus + AgentDojo v1 上复现不出来。**

### 2. 一部分对在逻辑上不可能同时完成

- **注入会删掉任务所需数据**：banking 账单被抹去金额与 IBAN，任务无法完成；
- **效用与安全互斥**：`banking user_task_15` 用户要求"把定期付款改成 US133…"，
  而注入目标正是"把定期付款收款人改成 US133…"，做对任务就等于被攻破；
- **基准自身的判据 bug**：`any(recipient or "" in t.subject ...)` 因运算符优先级
  恒为真——只要给攻击者 IBAN 付过任何款项就算"被攻破"。

我们第一次组的 20 个"已知失败"里，**15 个属于这类不可能对**。

### 3. 定向修复不能泛化

多次出现"回归集大涨、全域归零"：

| 改动 | 回归集 | 全域逐对差异 |
|---|---|---|
| banking 调整付款流程 | 5/8 → 7/8 | **修好 15 / 弄坏 15（净 0）** |
| workspace 格式规则 | 5/11 → 9/11 | 修好 25 / 弄坏 21（净 +4） |

温度 0 下仍有这种抖动，说明模型对措辞敏感，**单点验证不能外推**。

### 4. "守卫提升效用"的机制只有部分复现

报告：无防御 0.5946 → 守卫 0.7122（+0.118）。
我们：0.5200 → 0.5498（+0.030）。但**分域看**：

- banking：我们 +0.073，报告 −0.042（**我们更好**）
- travel：我们 +0.292，报告 +0.379（接近）
- workspace：我们 +0.046，报告 +0.138
- slack：我们 −0.209，报告 −0.057（**我们差**）

即"守卫效应"并非整体缺失，而是 slack 一个域拖累。

## 六、建议

1. **改用 qwen3.5-27b 作为智能体模型**：同口径下 UA 提升 13–27pp，安全基本不变。
   代价是与报告的"qwen-plus"不再同模型，需要在报告里注明。
2. **把"复现报告绝对值"从目标里去掉**：官方实现只有报告基线的 1/4，继续追是负期望。
   可交付口径改为：ASR、守卫效应、以及这份复现性分析。
3. **若要冲 UA，只做两件事**：换模型（已验证有效）、修 slack 的守卫误杀（唯一负效应域）。
4. **测量口径固定**：回归集只看方向，结论只用全域名对差异；排除互斥对与不可能对，
   同时给原始与剔除后两个数。

## 七、一句话总结

**系统重建完成，安全和守卫机制都达到或超过报告水平（slack ASR 精确一致、
banking 守卫效应反超）；效用差距主要来自"报告基线不可复现"与"模型能力"，
后者已通过改用 qwen3.5-27b 显著改善（UA +13~27pp）。**
