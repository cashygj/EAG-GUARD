# 消融与恢复机制：今日两次尝试的结论

## 1 消融三臂（对齐报告表 4-2）

报告里的"语义 vs 结构（25 对）"是：纯结构 8% / 0.48，纯结构+委托 44% / 0.92，
EAG 4% / 0.92。

现在 CLI 已支持复现这三臂：

```powershell
# 纯结构：白名单，每个参数只认用户直接指定
run_bench.py --judge none --structure-only ...
# 纯结构+委托：承认委托但不要裁判
run_bench.py --judge none ...
# EAG：默认
run_bench.py ...
```

实测（slack 25 对，qwen-plus-2025-04-28）：

| 臂 | 我们 ASR / UA | 报告 ASR / UA |
|---|---:|---:|
| 纯结构（白名单） | 16.00% / 0.88 | 8% / **0.48** |
| 纯结构+委托 | 16.00% / 0.92 | 44% / 0.92 |
| EAG | **4.00% / 0.68** | 4% / 0.92 |

**两处关键差异**：

1. **我们的"纯结构"罚不痛**（0.88 vs 报告 0.48）。报告的白名单会把大量合法动作
   挡掉，效用腰斩；我们的白名单只限制参数来源，对象参数里还有 id_scoped 跳过，
   所以几乎不疼。
2. **我们的"结构+委托"不漏**（16% vs 报告 44%）。报告的委托一放开就漏 44%，
   说明他们的结构与委托之间没有任何缓冲；我们这里还有 T/O 与对象白名单兜着。

这说明**我们的"结构"比报告的更宽容**。这既是好事（效用高）也是坏事（安全弱）。

## 2 恢复机制：定向续做（RecoveryNudge）

**做法**：只在"确实刚发生过拦截"且"模型这一轮没发起任何工具调用（想收尾）"时，
再推一次并明确要求继续；每任务最多 2 次。

**结果**（workspace 全域 235 对）：

| 配置 | ASR | UA |
|---|---:|---:|
| 无防御 | 14.83% | 0.5212 |
| 守卫（无续做） | 0.85% | 0.5234 |
| **守卫 + 续做** | 0.85% | **0.5191** |

**没有提升。** 诊断时算过，workspace 里"被拦后立刻收尾"的只有 7 对（约 0.03），
本来就在噪声带内，推不推都一样。

## 3 结论

- **恢复机制不是 workspace 的瓶颈**：拦后收尾的样本太少，改动再精细也淹没在噪声里。
- workspace 的 0.25 差距里，0.11 是智能体基线（0.52 vs 0.63），剩下的是
  "他们的守卫能提升效用"这个我们复现不出来的效应。
- 消融三臂已具备，但与报告的"纯结构"语义不同——我们的结构更宽容，
  这解释了为什么我们的 ASR 在某些臂上更低、UA 更高。
