# 四域优化与回归（全量测试前的收口）

## 1 这一轮修掉的真问题

### 1.1 状态报告改动**从未生效**（静默失败）

之前那版"拦截后告诉模型已完成什么"的编辑，替换字符串没匹配上，
代码里还是旧文案。更糟的是**三次测量（0.72/0.40/0.50）都以为是它的效果**，
实际来自别处。

现在用精确编辑落地，并写了回归测试钉住：

```python
assert "已经成功完成" in notice
assert "不是任务失败" in notice
```

### 1.2 弱反馈分支漏掉了进度信息

banking 走弱反馈分支，而状态报告只加在强反馈分支里——banking 一直拿不到
"已完成哪些"。现在弱反馈也会带一行进度。

### 1.3 解析器漏列工具（T 不完整）

实测 workspace 的 `delete_file`、travel 的 `create_calendar_event` 被判
"不在授权范围 T"，任务直接做不完。加了**动作词兜底**：

| 请求里出现 | 补进 T |
|---|---|
| delete / remove / 删除 | delete_file, delete_email, delete_calendar_event |
| send / email / 邮件 | send_email, send_direct_message |
| schedule / meeting / 预约 | create_calendar_event |
| reserve / book / 预订 | reserve_hotel, reserve_restaurant, reserve_car_rental |

只补工具集合里真实存在的工具；O 与 P 仍然管着对象与来源。

**workspace 因此从 0.68 → 0.76。**

## 2 新增回归测试（8 条）

`tests/test_regressions.py` 钉住的全是"曾经静默失效"的行为：

1. strict 参数在 untargeted 放宽下仍然保持窄口径
2. 授权范围描述与真实策略一致（不能写"只能由用户指定"却按 untargeted 执行）
3. 豁免字段在裁判可见的签名里被抹掉
4. 拒绝提示是"任务状态报告"（含已完成动作、明确"不是任务失败"）
5. 动作词兜底能补出隐含工具
6. `no_target` 读策略只放行无目标读取
7. 按域配置与报告表 4-2 一致
8. 图有六类节点

全部通过（共 85 个测试）。

## 4 噪声问题（重要）

banking 连跑三次：0.36 / 0.50 / 0.375，**标准差 0.077**。

也就是说 25 对切片上，任何小于 0.08 的差异都是噪声。之前若干"提升/下降"
的结论都落在这个带内，不可信。**全域测试必须优先看 105+ 对的结果。**

## 5 仍未解决

- travel 0.42 vs 0.64：模型有时把注入要求的邮件当成任务的一部分（要发给人）。
- banking 0.41 vs 0.72：模型用了注入里的 IBAN，被拦后没有回到账单里的 IBAN。
- 这两个都是"模型选错值"，守卫只能拦，不能替它选。
